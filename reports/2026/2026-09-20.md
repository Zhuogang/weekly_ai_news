# AI Research & Engineering Digest

**September 20, 2026 · Coverage: September 16–20**

Four ideas worth stealing:

- **Treat SSD as an MoE weight tier:** Edge0 changes routing itself so that tomorrow’s experts can be loaded while today’s token is computing.
- **A working system can be its own specification:** ProgramDistill has coding agents reverse-engineer behavior from reference applications, then grades reconstructed workflows by replay.
- **Structured data is getting a serious foundation-model treatment:** LimiX-2 tackles prediction, imputation and limited structural discovery with one 400M-parameter model.
- **Agent benchmarks are finally becoming systems benchmarks:** MLPerf now includes end-to-end retrieval and on-device agent workflows, though participation is still thin.

I checked these against Wednesday’s issue, so Retrieve-for-Train, Dream-RSI, HazardAuditor and the earlier inference items aren’t repeated. Several September 16 papers surfaced after that digest and are labeled accordingly. Hugging Face Daily Papers was a discovery feed; links below go to original papers, repositories and project posts.

Unless noted otherwise, results are author-reported and haven’t been independently reproduced here.

## 1. Edge0: don’t predict which experts to load—make the prediction the routing decision

*Inference paper, framework and checkpoints · September 16; surfaced after Wednesday’s issue*

Sparse MoEs reduce arithmetic but not storage. A 35B model quantized to four bits still occupies roughly 20–23 GB, and putting its experts on SSD creates a timing problem: you normally cannot know which layer-$N+1$ experts to fetch until layer $N$ finishes.

Edge0 introduces a small per-layer **prerouter** that selects next-token experts early enough to overlap SSD reads with computation. The subtle but important move is that the prediction becomes the model’s actual routing; there is no later “correct” route that can cause a cache miss. Because this changes the network, the authors distill an unmerged recovery LoRA along the altered, quantized execution path.

The paper reports roughly 20 tokens/s for a 35B MoE with about 3 GiB of peak active memory. The current repository’s more specific M4 Pro measurements are **14.9–17.7 tokens/s**, using a 23 GB checkpoint and 2.9 GiB of active memory. “Active memory” does not include the disk-resident weights, OS overhead or long-context KV growth.

Quality is not free: across five reported benchmarks, the 35B configuration averages 79.2 versus 83.2 for its FP16 teacher. AIME drops 6.1 points; MMLU-Pro also drops, despite an earlier repository description suggesting otherwise. This is learned architectural approximation, not lossless offload.

For edge deployment, the genuinely useful idea is broader than this implementation: **train the model around the storage hierarchy instead of expecting a generic checkpoint to tolerate paging afterward**.

**Availability:** the [paper](https://arxiv.org/abs/2609.18063), [Apache-2.0 framework and benchmarks](https://github.com/Edge0-AI/edge0), and 8B/35B checkpoints are public. Today’s implementation supports MLX on Apple Silicon; CUDA is only on the roadmap.

## 2. LimiX-2: one contextual model for tabular prediction and missing data

*Model and inference-code release · September 16*

LimiX-2 is a roughly **400M-parameter structured-data foundation model** that performs classification, regression and missing-value imputation without updating its parameters for each downstream dataset.

Conventional prior-fitted tabular networks usually learn something resembling $p(y \mid x,D)$: infer the target given one record and a contextual dataset. LimiX-2’s Contextual Mechanism Network instead tries to model the joint structure $p(x,y \mid D)$. Pretraining uses synthetic structural causal models with varied graphs, functions and observation processes; context-conditional masked modeling asks the network to reconstruct different parts of that generated structure.

That joint objective plausibly explains why the same representation can support prediction and imputation. The authors also argue that attention recovers causal skeletons—but I would keep that claim in a separate mental box. Learning statistical structure from synthetic SCMs is not equivalent to identifying causal direction in a changing production system with selection effects and hidden confounders.

The authors report first place on TabArena, TALENT and BCCO, including a **TabArena Elo of 1,935 versus 1,818 for TabFM+ and 1,789 for a four-hour AutoGluon configuration**. Those are the releasing team’s aggregate results; latency, memory and calibration on your particular table may matter more than a leaderboard Elo.

For applied work, this is interesting as a fast experimental baseline for:

- sparse operational tables with several plausible targets;
- cold-start tasks where per-dataset tuning is undesirable;
- joint prediction and imputation;
- probing whether pretrained synthetic mechanisms transfer to real sensor metadata.

**Availability:** [paper](https://arxiv.org/abs/2609.17488), [inference code and checkpoint](https://github.com/limix-ldm-ai/LimiX). The new LimiX-2 weights use a **non-commercial license**, unlike some earlier LimiX artifacts.

## 3. ProgramDistill: let a working application serve as the spec and verifier

*Benchmark paper · September 16; technical explanation published September 14*

Most coding benchmarks provide an issue description and tests. ProgramDistill asks a more realistic question: can an agent inspect a functioning reference application, infer what it does and recreate that behavior in an editable but incomplete application?

Its mine–craft–patch pipeline:

1. Explores an application and records replayable browser workflows.
2. Establishes prerequisite relationships among behaviors.
3. Removes the relevant implementation while preserving prerequisites.
4. Lets an agent repair the editable application using only black-box access to the reference.
5. Replays the workflow to grade the result without an LLM judge.

Across 26 applications, the pipeline discovered **1,975 reproducible behaviors** and generated 4,063 atomic and cumulative tasks. In full reconstruction, GPT-6 Astra recovered 49.15% of cumulative workflows; Claude Opus 5 recovered 28.81%. A working collection of features often failed to compose into a correct application.

The failure analysis is even more useful than the ranking: **59.2% of failed behaviors had never been observed in the reference**. Agents are not only weak implementers; they are weak experimentalists. As tasks deepen, they also spend less observation and validation effort per required behavior.

That suggests an evaluation metric I’d like to see more often: not merely “did the agent finish?”, but **which behaviors did it discover, which did it test after its last relevant edit, and which state transitions did it misunderstand?**

Limitations: the initial domain is 26 web applications, replay tests capture only instrumented behavior, and qualities such as accessibility, visual fidelity and maintainability are mostly outside the verifier. The complete benchmark dashboard is also still forthcoming.

Read the [excellent technical walkthrough](https://microsoft.github.io/debug-gym/blog/2026/09/programdistill/) or the [paper](https://arxiv.org/abs/2609.18805).

## 4. JEPA-Anything: one predictive principle across very different worlds

*Paper and code · September 17*

JEPA-Anything is the week’s ambitious, possibly-overambitious research bet.

Its Orthogonal Predictive Factorization replaces a monolithic latent target with complementary factors, learned through separate predictive pathways and recombined for downstream prediction, intervention or rollout. The authors test this pattern across vision, control, biological systems, clinical trajectories, molecular dynamics, weather and physical fields.

One clarification matters: this is **not one universal checkpoint modeling every domain**. Each domain retains its own observations, encoders and context–target construction. The proposed universality is the factorized predictive core and interface.

Author-reported evidence includes:

- Improvements over matched JEPA baselines on all ten tested dynamics tasks.
- 34.8% lower single-intervention error in Interventional Pong.
- Best compared one-step and 100-step molecular errors across four systems.
- A factor-selected biological intervention supported across cell cultures, organoids, tumor fragments and mice.
- Latent orbital modes recovering a Keplerian exponent of approximately −1.5.

That breadth is impressive but makes evaluation tricky. The tasks, metrics and baselines differ dramatically; success across them supports “this factorization is reusable” more strongly than “we have discovered a general world-model architecture.” The biological claim in particular deserves domain-specialist review before being treated as causal discovery.

**Availability:** [paper](https://arxiv.org/abs/2609.20800) and [Apache-2.0 repository](https://github.com/Gen-Verse/JEPA-Anything). The repository provides a reusable core, task-design tools, checkpoints and an executable structural example; it is not yet a one-command reproduction of every experiment.

## 5. ScienceIDE turns legacy scientific software into agent environments

*Paper and model family · September 16; repository expanded September 19*

Scientific repositories contain executable knowledge, but their tests often check whether software runs—not whether the resulting physics or numerical behavior remains correct.

ScienceIDE wraps pinned scientific packages in containerized tasks with domain-specific cases and numerical acceptance criteria. Agents repair injected semantic defects or reimplement missing routines; the verifier recompiles the software, reruns scientific cases and compares numerical outputs with references.

This creates a useful substrate for supervised training, RL and evaluation because the reward comes from restored scientific behavior, not matching a gold patch. Released models include PhAI-IDE at 4B, 9B and 72B parameters.

Reported gains are distinctly non-uniform:

- A 4B RL run improves from 0.357 to 0.857 verifier reward on a LAPS environment.
- The 4B SFT model gains 6.99 points on CodeXGLUE defect detection.
- A 9B model gains 36 points on BBH Word Sorting.
- The 72B result on CodeXGLUE refinement improves only 0.77 points.
- The paper also reports a regression on HumanEvalFix Python.

That uneven transfer is actually reassuring: it is evidence against a suspiciously universal “scientific training makes everything better” story.

The design pattern is valuable for applied research teams: package a real simulator or evaluation stack as a deterministic environment, inject meaningful faults, and train agents against domain outcomes. The expensive part is not the agent framework; it is writing scientifically defensible acceptance criteria.

**Availability:** [paper](https://arxiv.org/abs/2609.19134), [models and training code](https://github.com/aitofound/ScienceIDE). This remains a preview: 15 of 64 environments and 30 of 85 hard tasks are public.

## 6. Agora: use Git commits as the memory of a research community

*Multi-agent research system · September 16; surfaced after Wednesday’s issue*

Wednesday’s Dream-RSI used historical search trees to improve an orchestration policy. Agora addresses a different coordination problem: how do independent research agents accumulate results without sharing one enormous conversation or repeatedly trying the same idea?

Each experiment, failure, hypothesis or reproduction becomes an immutable Git commit. Parent relationships encode provenance, a derived index exposes promising and neglected branches, and evidence scores reward independent reproduction rather than self-citation.

In the reported run, 13 model workers spent nearly 12 days initializing a frozen 119.6M-parameter model from 141 incompatible donor models—without training data or gradient updates. They produced 1,703 contributions and reduced the evaluator from 3.39 to **1.899 bits per byte**, closing 62% of the gap to a trained GPT-2-sized reference. The winning result had a 145-commit ancestry across 15 accounts and received 165 successful reproductions.

Two reality checks keep this from becoming “swarm intelligence solved research”:

- Approximately 98% of the improvement arrived on the first day; more than a thousand later contributions found only the last 0.03 bpb.
- A human intervened once to pull the population out of a monoculture.

The authors explicitly say a compute-matched controlled comparison is still needed. Good. The run demonstrates provenance and cumulative construction; it does not yet prove that a Git-mediated swarm beats one agent or several isolated agents per unit compute.

For a technical lead, the transferable idea is to represent research state as **claims plus executable evidence and ancestry**, not a pile of chat transcripts.

Read the [paper](https://arxiv.org/abs/2609.18094) and inspect the [public project and experiment trace](https://github.com/yifanzhang-pro/Agora). The repository currently documents the system and run; it does not contain a complete released implementation.

## 7. Same eight samples, six times the latency: test-time compute needs a schedule

*Systems measurement paper · September 16*

“Generate eight candidates” does not specify whether you issue one batch of eight, eight serial calls or something between those extremes.

This paper fixes the candidate count at eight and compares schedules of 1×8, 2×4, 4×2 and 8×1. On A100s, eight serial calls consumed **4.64–4.86× more gross GPU energy** and produced **5.77–6.12× higher P95 latency** than one call containing eight candidates. The pattern was repeated across separately scheduled A100 nodes and a smaller SciQ/V100 experiment.

The recommendation is delightfully mundane and important: report calls × batch size, latency, GPU-hours and device energy alongside candidate count and accuracy.

The boundaries are equally clear. Experiments use Phi-3-mini and Qwen2.5-1.5B on GSM8K and SciQ; independent candidates can batch neatly, and sufficient memory is assumed. Online serving with variable lengths, shared batching, KV reuse or heterogeneous tools may have a different optimum.

Still, if someone says “best-of-8 costs eight samples,” your next question should be: **scheduled how?**

[Read the paper](https://arxiv.org/abs/2609.19499).

## 8. MLPerf Inference v6.1 starts measuring complete AI systems

*Benchmark release and technical analysis · September 16–17*

The significant part of MLPerf Inference v6.1 is not another giant tokens-per-second number. It is the arrival of workloads that cross component boundaries:

- End-to-end question answering and vector-database retrieval.
- An agentic edge benchmark with multistep behavior.
- An interactive Qwen3-based VLM scenario.
- An updated GPT-OSS-120B interactive track that permits speculative decoding.

The release contains submissions from 30 organizations covering 120 systems. MLCommons reports median per-accelerator Llama-2-70B server performance improving **5.58× across six benchmark rounds**, reflecting a mix of newer hardware, lower precision and serving-software improvements.

This is a healthy direction. Real applications experience retrieval, preprocessing, scheduling, model execution and orchestration together. Component microbenchmarks remain necessary, but they cannot tell you whether an agent loop meets an end-to-end latency or power budget.

It is early, though. Agentic edge has only five submitted systems, while each new end-to-end datacenter benchmark has one. Those tracks are better read as an emerging measurement contract than a mature leaderboard. Also keep Closed and Open divisions separate: Closed controls the model for comparability; Open intentionally allows more optimization freedom.

Read the [MLCommons analysis](https://mlcommons.org/2026/09/chairs-mlperf-inference-v6-1/) and consult the linked result tables before comparing vendor headlines.

## If you open only two tabs

1. **[Edge0](https://github.com/Edge0-AI/edge0)** — the most immediately inspectable systems release. The paper’s best idea is that model routing and storage scheduling may need to be trained together.
2. **[ProgramDistill](https://microsoft.github.io/debug-gym/blog/2026/09/programdistill/)** — the best agent-evaluation read. It turns black-box behavioral discovery, implementation and exact replay into one coherent benchmark.

**One concrete idea to explore:** convert 20 difficult retrieval → VLM verification cases into replayable behavioral traces. For each case, record the observations available, expected state transitions, acceptable abstention and final decision. Then deliberately remove one capability—query expansion, visual crop selection, reranking or evidence validation—and ask an agent or optimizer to restore the reference behavior.

Measure three things separately:

- Did it inspect the evidence required to discover the behavior?
- Did it reproduce the decision?
- Did it rerun the exact workflow after its final change?

The discussion-worthy question is: **Are our failures mainly model errors, implementation errors, or failures to perform the right experiment before deciding?**
